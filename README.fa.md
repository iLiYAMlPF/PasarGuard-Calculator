# پاسارگارد کلکولیتور (Sum Bot)

🇬🇧 [English README](README.md)

ربات تلگرامی که **حجم (Data Limit)** کاربرانی را که پنل [پاسارگارد](https://github.com/PasarGuard/panel) می‌سازد (پیام‌های `#Create_User`) جمع می‌زند و **به تفکیک Belongs To** گزارش می‌دهد. گزارش هفتگی و جمع کل دارد و هفته‌ی ایرانی را هر **جمعه ساعت ۲۳:۵۹ (به وقت تهران)** خودکار می‌بندد.

نمونه‌ی گزارش:

</div>

```
📅 هفته 1 (1405/08/11 تا 1405/08/15)
━━━━━━━━━━━━━━━
👤 MSN — 2 کاربر — 90 GB
   • Bijan — 60 GB
   • Ali — 30 GB
━━━━━━━━━━━━━━━
📊 جمع کل: 140 GB
👥 تعداد کاربر: 3
```

<div dir="rtl">

## پیش‌نیازها

- یک سرور اوبونتو/دبیان با دسترسی root (SSH). همان سرور پنل پاسارگارد هم مشکلی ندارد.
- یک گروه تلگرام (اگر از تاپیک استفاده می‌کنید، تاپیک مربوطه)
- اعلان‌های تلگرام پاسارگارد باید داخل همین گروه یا تاپیک ارسال شوند.

## نصب

### ۱. ساخت ربات جدید
در [@BotFather](https://t.me/BotFather) دستور `/newbot` را بزنید و توکن را بردارید.
**حتماً ربات جدید بسازید** و از توکن ربات خود پاسارگارد استفاده نکنید.

### ۲. جمع کردن اطلاعات لازم
اسکریپت نصب این چهار مورد را از شما می‌پرسد:

| مورد | توضیح |
|---|---|
| توکن ربات | از @BotFather |
| آیدی گروه | آیدی عددی گروه که با `-100` شروع می‌شود (مثل `-1001234567890`). گروه را در web.telegram.org باز کنید و از آدرس بردارید، یا یک پیام از گروه را برای @getidsbot فوروارد کنید |
| آیدی تاپیک | تاپیکی که ربات باید بخواند. برای تاپیک General عدد `1` |
| آیدی عددی شما | آیدی عددی خودتان در تلگرام. فقط همین شخص می‌تواند از ربات استفاده کند. با ارسال `/myid` به ربات می‌گیرید (در ابتدا می‌توانید خالی بگذارید) |

### ۳. اجرا روی سرور
با SSH وارد سرور شوید (کاربر root) و این را بزنید. **از داخل پوشه‌ی `/opt/sum-bot` اجرا نکنید.**

</div>

```bash
cd /
bash <(curl -fsSL https://raw.githubusercontent.com/iLiYAMlPF/PasarGuard-Calculator/main/install.sh)
```

<div dir="rtl">

اسکریپت همه‌چیز را نصب می‌کند، چهار سؤال بالا را (به انگلیسی) می‌پرسد، سرویس systemd می‌سازد و ربات را روشن می‌کند. در پایان باید پیام `✅ Bot is running.` را ببینید.

سؤال‌های اسکریپت و جوابشان:

| سؤال | چه بنویسید |
|---|---|
| `Enter the bot token` | توکن ربات (هنگام تایپ دیده نمی‌شود، paste کنید و Enter بزنید) |
| `Enter the group chat ID` | آیدی گروه، مثل `-1001234567890` |
| `Enter the topic ID` | آیدی تاپیک. برای General فقط Enter |
| `Enter YOUR numeric Telegram user ID` | آیدی عددی خودتان، یا Enter برای رد کردن |

### ۴. تنظیمات تلگرام (الزامی)
بدون این مرحله ربات پیام‌های پاسارگارد را نمی‌بیند:

1. ربات را به گروه اضافه کنید و **ادمین** کنید.
2. در @BotFather دستور `/setprivacy` را بزنید، ربات را انتخاب کنید و **Disable** کنید. بعد ربات را از گروه حذف و دوباره اضافه کنید و دوباره ادمین کنید.
3. در @BotFather گزینه‌ی **Bot-to-Bot Communication Mode** را برای **هر دو ربات** (ربات پاسارگارد و این ربات) روشن کنید.

### ۵. قفل کردن روی خودتان
اگر در نصب آیدی خودتان را خالی گذاشتید: در گروه `/myid` بزنید، بعد روی سرور:

</div>

```bash
nano /opt/sum-bot/.env        # OWNER_IDS=آیدی_عددی_شما
systemctl restart sum-bot
```

<div dir="rtl">

### ۶. تست
- در تاپیک `/week` بزنید. ربات باید جواب بدهد.
- در پنل یک کاربر بسازید. ربات باید روی پیام پاسارگارد 👍 بزند.

## دستورها

| دستور | کار |
|---|---|
| `/week` | گزارش هفته‌ی جاری (بسته نمی‌شود) و زمان بستن خودکار بعدی |
| `/week 3` | گزارش هفته‌ی بسته‌شده‌ی شماره ۳ |
| `/closeweek` | بستن دستی هفته (با دکمه‌ی تأیید) |
| `/total` | جمع کل همه‌ی هفته‌ها |
| `/weeks` | فهرست هفته‌های بسته‌شده |
| `/analyze` | تحلیل کامل: جمع، میانگین، سهم هر Belongs To، بزرگ‌ترین اکانت‌ها و فهرست هفته‌ها |
| `/analyze help` | آموزش ایمپورت پیام‌های قدیمی |
| `/price` | نمایش قیمت‌ها. `/price MSN 1500` = قیمت هر گیگ برای یک Belongs To، `/price all 1000` = قیمت پیش‌فرض، `/price MSN off` = حذف |
| `/userprice Ali 90000` | قیمت ثابت یک کاربر (روی قیمت هر گیگ اولویت دارد) |
| `/sales` | فروش به تومان برای هر Belongs To: هفته‌ی جاری؛ `/sales 3` یک هفته‌ی بسته‌شده؛ `/sales total` همه؛ با `full` ریز هر کاربر |
| `/add Ali 30 MSN` | افزودن دستی یک ثبت (نام‌کاربری، حجم، Belongs To) |
| `/remove Ali` | حذف یک ثبت (با دکمه انتخاب می‌کنید کدام) |
| `/backup` | ارسال بکاپ دیتابیس (فقط در پیوی) |
| `/status` | عیب‌یابی: آیدی‌ها، دسترسی ادمین و اینکه پیام‌های پاسارگارد دیده می‌شود یا نه |
| `/help` | فهرست دستورها |
| `/version` | نمایش نسخه‌ی نصب‌شده‌ی ربات |
| `/update` | بررسی نسخه‌ی جدید در GitHub و آپدیت ربات (فقط مالک). `/update force` حتی اگر شماره‌ی نسخه فرق نکرده باشد آپدیت می‌کند |
| `/myid` | نمایش آیدی عددی شما |

به دستورهای گزارش می‌توانید `short` (خلاصه) یا `full` (کامل) اضافه کنید، مثل `/total full` یا `/week short`.

بعد از بسته شدن هفته (دستی یا خودکار)، آن هفته دیگر در `/week` جمع نمی‌شود و شمارش هفته‌ی جدید از صفر شروع می‌شود. هفته‌های بسته‌شده در `/total` و `/weeks` می‌مانند.

## تحلیل پیام‌های قدیمی

ربات‌های تلگرام **نمی‌توانند پیام‌های قدیمی گروه را بخوانند**، پس تاریخچه را باید یک بار از خروجی (Export) گروه وارد کنید:

1. در **Telegram Desktop** (نسخه‌ی کامپیوتر) گروه را باز کنید ← منوی ⋮ ← **Export chat history**.
2. همه‌ی گزینه‌های رسانه (عکس، ویدیو، فایل...) را خاموش کنید تا فقط پیام‌ها ذخیره شود.
3. Format را روی **Machine-readable JSON** بگذارید و Export کنید.
4. فایل `result.json` را در **پیوی ربات** برایش بفرستید (برای این کار `OWNER_IDS` باید تنظیم شده باشد).

ربات همه‌ی پیام‌های `#Create_User` را می‌خواند، آن‌ها را به هفته‌های ایرانی درست تقسیم می‌کند (هفته‌های بسته‌شده + هفته‌ی جاری که باز می‌ماند) و تحلیل کامل می‌فرستد.
فرستادن دوباره‌ی همان فایل مشکلی ندارد و پیام‌های تکراری شمرده نمی‌شوند. بعد از ایمپورت، شماره‌ی هفته‌ها بر اساس تاریخ دوباره مرتب می‌شود.
بعداً هر وقت خواستید با `/analyze` دوباره تحلیل را ببینید. فایل تا ۲۰ مگابایت پشتیبانی می‌شود.

## قیمت و فروش

1. قیمت هر گیگ را تعیین کنید: `/price MSN 1500` (برای یک Belongs To) یا `/price all 1000` (پیش‌فرض بقیه).
2. اگر خواستید برای یک کاربر قیمت ثابت بگذارید: `/userprice Ali 90000`.
3. `/sales` نشان می‌دهد هر Belongs To چند تومان فروش داشته. وقتی قیمت تعیین شده باشد، گزارش فروش بعد از هر بستن هفته هم خودکار فرستاده می‌شود.

## بکاپ و ریستور

- `/backup` در پیوی ربات، فایل دیتابیس را برایتان می‌فرستد. با `AUTO_BACKUP=1` بعد از هر بستن خودکار هفته هم بکاپ می‌آید.
- **ریستور:** همان فایل `.db` را در پیوی ربات بفرستید و دکمه‌ی **ریستور** را بزنید. قبلش یک نسخه‌ی ایمن از داده‌ی فعلی کنار دیتابیس ذخیره می‌شود.
- در بکاپ توکن نیست (توکن فقط در `.env` است).

## عیب‌یابی: ربات کاربر جدید را ثبت نمی‌کند

دستور `/status` را **داخل همان تاپیکی که پاسارگارد پیام می‌فرستد** بزنید. آیدی چت و تاپیک، ادمین بودن ربات، دسترسی حذف پیام و اینکه پیام `#Create_User` دیده شده یا نه (و اگر نادیده گرفته شده چرا) را نشان می‌دهد. اگر پاسارگارد در **کانال** پیام می‌فرستد، ربات را ادمین همان کانال کنید.

## تنظیمات

فایل `/opt/sum-bot/.env` را ویرایش کنید و بعد `systemctl restart sum-bot` بزنید.

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `BOT_TOKEN` | — | توکن ربات (الزامی) |
| `CHAT_ID` | خالی | آیدی گروه. خالی یعنی در هر گروهی که ربات اضافه شود کار کند |
| `TOPIC_ID` | `1` | تاپیکی که خوانده می‌شود (`1` = General) |
| `OWNER_IDS` | خالی | آیدی‌های عددی افراد مجاز (با کاما جدا کنید). خالی یعنی همه گزارش را می‌بینند و فقط ادمین‌های گروه می‌توانند هفته را ببندند |
| `AUTO_CLOSE` | `1` | `0` بستن خودکار هفته را خاموش می‌کند |
| `WEEK_END_DAY` | `fri` | روز پایان هفته: `sat sun mon tue wed thu fri` |
| `WEEK_END_TIME` | `23:59` | ساعت بستن خودکار (به وقت تهران) |
| `TIMEZONE` | `Asia/Tehran` | منطقه‌ی زمانی برای مرز هفته و تاریخ‌ها |
| `COUNT_TAGS` | `#Create_User` | اعلان‌هایی که شمرده می‌شوند |
| `UPDATE_CHECK` | `1` | هر ۱۲ ساعت GitHub را چک می‌کند و اگر نسخه‌ی جدید باشد به مالک‌ها پیام می‌دهد |
| `VERSION_URL` | فایل `VERSION` مخزن | جایی که شماره‌ی آخرین نسخه از آن خوانده می‌شود |
| `UPDATE_BRANCH` | `main` | شاخه‌ای که `/update` از آن می‌گیرد |
| `DELETE_PATTERNS` | `User not found` | پیام‌هایی که این متن‌ها را دارند حذف می‌شوند (چند عبارت را با `|` جدا کنید، خالی = خاموش). ربات باید ادمین با دسترسی *Delete messages* باشد |
| `AUTO_BACKUP` | `1` | بعد از هر بستن خودکار هفته، بکاپ به پیوی مالک‌ها فرستاده می‌شود |
| `CURRENCY` | `تومان` | واحد پول در گزارش فروش |
| `REPLY_EACH` | `0` | `1` یعنی بعد از هر پیام شمرده‌شده جواب بدهد |
| `REACT` | `1` | `1` یعنی روی پیام شمرده‌شده 👍 بزند |

## آپدیت

### گذاشتن نسخه‌ی جدید (شما، در GitHub)
1. فایل‌های مخزن را ویرایش کنید (مثلاً `sum_bot.py`).
2. عدد داخل فایل `VERSION` را عوض کنید (مثلاً `1.0.0` به `1.1.0`).
3. اگر خواستید تغییرات را در `CHANGELOG.md` بنویسید.
4. در شاخه‌ی `main` ذخیره (Commit) کنید.

### آپدیت روی سرور
یکی از این سه راه:

- **از داخل سرور:** `sum-bot update`
- **از داخل تلگرام:** در پیوی ربات `/update` را بفرستید (فقط مالک) و دکمه‌ی **آپدیت** را بزنید.
  اگر `UPDATE_CHECK=1` باشد، ربات خودش هم وقتی نسخه‌ی جدید بیاید به شما پیام می‌دهد
  (یک بار ربات را در پیوی استارت کنید تا اجازه‌ی پیام دادن به شما را داشته باشد).
- **اجرای دوباره‌ی نصب:** همان دستور مرحله‌ی نصب.

`.env` و `data.db` همیشه حفظ می‌شوند و ربات چند ثانیه ریستارت می‌شود.

> سروری که قبل از اضافه شدن سیستم آپدیت نصب شده، باید **یک بار** دستور نصب را اجرا کند تا دستور `sum-bot` و `/update` را بگیرد.

### دستور `sum-bot` روی سرور

| دستور | کار |
|---|---|
| `sum-bot update` | دریافت آخرین نسخه و ریستارت |
| `sum-bot version` | نمایش نسخه‌ی نصب‌شده |
| `sum-bot status` | وضعیت سرویس |
| `sum-bot logs` | لاگ زنده |
| `sum-bot restart` | ریستارت ربات |
| `sum-bot config` | ویرایش `.env` و ریستارت |
| `sum-bot uninstall` | حذف ربات (با بکاپ دیتابیس در `/root`) |

## حذف

</div>

```bash
sum-bot uninstall
```

اول تأیید می‌گیرد و یک بکاپ از دیتابیس در `/root/sum-bot-data.db.bak` ذخیره می‌کند.

## عیب‌یابی

</div>

```bash
systemctl status sum-bot
journalctl -u sum-bot -n 50 --no-pager
```

<div dir="rtl">

- **خطای `203/EXEC` در لاگ:** venv ساخته نشده؛ دستور نصب را دوباره اجرا کنید.
- **ربات به `/myid` جواب می‌دهد ولی پیام‌های پاسارگارد را نمی‌بیند:** مرحله‌ی ۴ را چک کنید (ادمین بودن، Privacy خاموش، Bot-to-Bot Mode برای هر دو ربات).
- **در گروه هیچ جوابی نمی‌دهد:** `CHAT_ID` (با علامت منفی و `-100`)، `TOPIC_ID` و `OWNER_IDS` را چک کنید. یک رقم اشتباه همه‌چیز را قفل می‌کند.
- **خطای `Conflict: terminated by other getUpdates`:** همین توکن جای دیگری هم در حال اجراست. از توکن ربات پاسارگارد استفاده نکنید و ربات را دو بار اجرا نکنید.

> ⚠️ فایل `.env` و توکن را هرگز روی GitHub نگذارید. اگر توکن لو رفت، در @BotFather با `/revoke` بی‌اعتبارش کنید.

</div>
